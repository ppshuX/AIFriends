# AI 协作说明设计

## 背景

AIFriends 的近期维护包含由 OpenAI Codex 辅助完成的仓库分析、实现、测试和文档工作，但当前公开文档没有说明 AI 协作边界。项目需要一段简短、可核查的公开声明，既承认工具贡献，也明确主要维护者对合并结果承担最终责任。

## 目标

- 在中文和英文 README 中增加语义对等的 AI 协作说明。
- 准确描述 Codex 的辅助范围：仓库分析、实现辅助、测试和文档。
- 明确所有变更均由项目维护者审核、验证并决定是否合并。
- 使用真实的 OpenAI Codex GitHub App 账号作为本次提交的共同作者，使 GitHub 能正确展示贡献归属。

## 非目标

- 不修改应用代码、配置、依赖或运行行为。
- 不重写已经合并的 Git 历史。
- 不为了增加提交数量制造空提交或无意义改动。
- 不将 Codex 描述为项目所有者、主要维护者或最终责任人。

## 文档设计

在两份 README 的贡献说明之后、许可证之前增加独立小节：

- 中文标题：`AI 协作说明`
- 英文标题：`AI Collaboration Disclosure`

正文只包含两层事实：

1. OpenAI Codex 辅助了部分仓库分析、实现、测试和文档工作。
2. 所有变更均由项目维护者审核和验证，是否合并及后续维护责任由项目维护者承担。

中英文版本必须语义对等，不列举无法核实的工作量、比例或自动化程度，也不使用宣传性措辞。

## 提交归属

提交的主要作者保留为项目维护者，并在提交消息末尾加入：

```text
Co-authored-by: Codex <267193182+codex@users.noreply.github.com>
```

该邮箱对应 GitHub 用户 [`@codex`](https://github.com/codex)，其公开资料标识为 OpenAI 的 coding agent。共同作者信息只用于确有 Codex 参与的改动，不作为未来提交的强制模板。

## 验证

- 检查中文和英文 README 的标题、辅助范围和责任归属逐项对应。
- 运行 `git diff --check`，确保没有格式错误或冲突标记。
- 验证 README 中的相对链接仍可解析。
- 确认差异仅包含规格文档与两份 README；应用构建产物不得进入提交。
- 推送后检查 GitHub 提交页面是否识别 Codex 为共同作者；Contributors 区域允许 GitHub 缓存延迟。

## 风险与回滚

主要风险是措辞夸大 AI 自主性或弱化维护者责任。通过限定辅助范围并明确审核、验证和合并责任来规避。若项目以后调整 AI 使用政策，可独立修改或删除该小节；此变更不影响任何运行数据或部署。
